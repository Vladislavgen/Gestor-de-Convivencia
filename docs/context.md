## Продукт

Веб-приложение для людей, которые живут вместе. Они делят аренду и общие траты, записывают личные расходы и обязанности и видят, кто кому сколько должен.

Один аккаунт Firebase принадлежит одному hogar. Сальдо считает приложение, не Gemini. Суммы хранятся в сентаво; остаток равного деления получает последний участник.

Вне этой версии: банковские переводы и Mercado Pago, фото чеков, почта и push, нативное приложение, несколько hogares на аккаунт.

## Что делать дальше

Идти по приоритету Alta. Пока нет входа и hogar, остальные экраны не на чем проверить.

1. **RF-01–RF-03.** Firebase Auth: почта и пароль и Google на одном экране. Создание hogar с кодом приглашения. Вход в существующий hogar по коду. Один аккаунт — один hogar.
2. **RF-04, RF-13, RF-14.** Имя участника, передача роли администратора, деактивация без удаления истории, подтверждение перед удалением.
3. **RF-05–RF-12.** Правило аренды, один cargo на период, общий расход и четыре способа деления, сальдо, минимальные переводы, платёж между участниками.
4. **RF-15.** Фраза в Gemini даёт черновик расхода. В Firestore он попадает только после подтверждения. При ошибке API остаётся ручная форма RF-07. Ключ Gemini не попадает в клиентский бандл: вызов идёт не из браузера с `VITE_`.
5. **Media, RF-16–RF-25.** Личные расходы, категории, обязанности, закрытие месяца, сводка, фильтры, CSV.
6. **Сдача.** Репозиторий GitHub с коммитами всех участников, ветки и pull requests. Деплой на Vercel или Firebase Hosting с непрерывной выкладкой из GitHub. На campus один человек сдаёт имена, тему в две строки, ссылку на репозиторий и ссылку на прод.

Правила Firestore: без сессии данных нет, чужой hogar не читается (RNF-05). Ошибки Firebase и Gemini видны на экране, основные сценарии не оставляют необработанных ошибок в консоли (RNF-11).
